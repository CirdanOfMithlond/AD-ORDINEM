# Reviewer Guide

This guide helps reviewers understand the public AD-ORDINEM repository quickly.

## Status in One Paragraph

AD-ORDINEM is an early public specification and reference architecture, not a completed production system. The repository publishes the reviewable public layer while the full technical white paper, additional examples, validation notes, and safe publication boundary are completed.

## Review Path

1. Read `docs/openai-oss-reviewer-note.md` for the support-request status clarification.
2. Read `README.md` for project scope.
3. Read `docs/project-brief.md` for the short project rationale.
4. Read `docs/architecture-overview.md` for the public architecture model.
5. Read `docs/public-whitepaper-summary.md` for the public summary.
6. Review `examples/change-record.yaml` and `examples/minimal-governance-manifest.yaml`.
7. Review `ROADMAP.md` and `docs/publication-boundary.md` for staged publication scope.
8. Review open issues for active public specification work.

## What To Look For

- deterministic infrastructure change records;
- governance manifests;
- rollback-aware review semantics;
- evidence-oriented change representation;
- explicit publication boundaries;
- planned validation work.

## Repository Status

AD-ORDINEM is in early public specification stage. The repository will be expanded through the technical white paper, examples, validation notes, schemas, and reference materials.

Associated implementation work is being prepared separately and should not be treated as production-ready public software until it is reviewed, documented, and published within the stated boundary.
